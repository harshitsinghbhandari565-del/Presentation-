# Experimental browser-local MariaDB

The separate `/sql-workbench/mariadb` page runs **MariaDB 13.1.0 preview**, not Oracle MySQL. It is an experimental educational option: MySQL syntax and behavior are not fully compatible. SQLite remains the default and its existing browser-only sandbox and database file import/export are unchanged. No visitor queries are sent to Supabase or a database server. No production database changes, hosted database, or paid service are required.

## Usage and limitations

- This mode loads roughly 17 MB of WebAssembly on first use and needs a modern browser with `SharedArrayBuffer` and cross-origin isolation. Open the page directly; an embedded preview or restrictive proxy can prevent isolation. The route and its workers have scoped COOP/COEP headers; the SQLite page does not. The mode links use full document navigations because client-side navigation alone does not apply document isolation headers.
- Each page starts with an empty `scratch` user database selected. The engine's empty `test` database is removed on initialization; the required `information_schema` remains visible in `SHOW DATABASES`. Every visitor has a separate in-memory worker. There are no sample tables.
- Reset/new, switching away, refresh, stopping or timing out destroys all temporary database data, including other databases made during the session. Reset and the explicit engine-switch controls confirm first. The MariaDB SQL draft is saved separately in sessionStorage and can be downloaded as SQL; it is not a database backup. MariaDB database import/export and SQLite's multi-tab, history, schema explorer and result sorting are not implemented for this experimental mode. Do not enter sensitive data on shared devices.
- One statement or selected statement is executed per run. The guard rejects multiple statements, executable comments and backslashes in quoted text to avoid silently ignoring trailing SQL. This deliberately excludes some valid MariaDB syntax and stored routine definitions. It is a usability guard, **not a security boundary or a full SQL parser**. SQL may change state before an error; transactions may remain open.
- Results are capped at 500 rows, 100,000 cells, and approximately 1 MB of retained text. Duplicate column names are rejected because upstream represents rows as objects; use unique column aliases. Binary values are shown by size. CSV contains retained rows only. **Upstream materializes the complete result before display caps are applied**, so limits and the 10-second worker watchdog are not hard memory/CPU quotas; a large query may exhaust device memory. Startup timeout is 45 seconds.
- COEP can affect third-party resources embedded into this particular route and site navigation; test any new integration. Deployment hosting/CDN bandwidth limits still apply even though execution happens in the browser. On the existing Vercel Hobby plan exceeding free usage may pause service; a hard zero-infrastructure-cost guarantee depends on maintaining that plan and reviewing provider terms.

## Engine and licence

`lite4mariadb@0.1.2` is pinned by the lockfile, with upstream source at [commit 24be9371a2f6c71250a2356631ad6feab2280b02](https://github.com/shyim/lite4mariadb/tree/24be9371a2f6c71250a2356631ad6feab2280b02). The npm package supplies its GPL-2.0-only `COPYING` notice. `scripts/copy-mariadb-assets.mjs` copies the unmodified npm distribution and licence to `public/sql/mariadb/` in `predev` and `prebuild`; generated binaries are ignored in Git. The public page links to both the licence and corresponding source. Review licence and source-distribution obligations before redistributing; these notes are not legal advice. Upstream is an early-stage third-party project; review and update deliberately rather than treating this preview as production-grade.

## Validation

`npm run check` covers lint, TypeScript, unit tests, database tests and production build. `tests/e2e/mariadb-workbench.spec.ts` exercises a real browser worker, version, `SHOW DATABASES`, create/use/table/insert/select, session isolation, reset, draft persistence, SQL guard, stop, mobile layout and an axe smoke test. `tests/e2e/sql-workbench.spec.ts` covers existing SQLite functionality. Tests in Chromium do not establish compatibility with all browsers, embedded previews or production load.
