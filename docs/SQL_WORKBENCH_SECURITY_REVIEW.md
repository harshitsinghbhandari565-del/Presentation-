# SQL Workbench hosted security and regression review

## Scope and current status

Reviewed the repository at `8a6f455`, the Vercel application, and the existing Supabase project. No database migration, record mutation, account creation, RLS disabling, paid service, or PostgreSQL/MySQL execution was performed for this milestone. The public application serves `/sql-workbench` and the published-only `/sql-workbench/library`; the latter currently reports no published shared queries. The database has one administrator membership and zero shared-query records or versions.

**The hosted administrator and direct visitor authorization workflows are not fully verified.** The available management connector is privileged and is not a legitimate administrator browser login or an anonymous PostgREST client. The sandbox cannot directly connect to the deployed Vercel or Supabase hosts; the page fetcher can retrieve public web pages but does not provide an authenticated browser session or arbitrary HTTP methods. Do not interpret the management connector's ability to inspect metadata as evidence that the visitor API was tested. A real admin sign-in/create/publish/edit/unpublish and anonymous HTTP read/insert/update/delete/IDOR test still require an approved real browser/API environment. No administrator password, token, or service-role key was requested.

## Hosted checks actually performed

- Anonymous GET of `/sql-workbench` and `/sql-workbench/library` returned the expected workbench and empty library pages. Anonymous GET of `/admin/sql-queries` redirected to administrator sign-in. This does not test direct server actions or the Supabase REST API, and an empty table cannot establish whether published and unpublished rows are isolated.
- The two hosted shared-query tables have RLS enabled. The SELECT policy exposes published rows to anon/authenticated and permits administrators to see drafts; INSERT and UPDATE are restricted to authenticated administrators; versions are SELECT-only for administrators. Both tables have no visitor DELETE policy. Anonymous column grants exclude author identity and creation time, and history has no anonymous SELECT grant. Authenticated users have INSERT/UPDATE grants on the query table but remain constrained by RLS. The table owner and `service_role` are privileged; history is append-only for normal application users, not tamper-proof against privileged operators.
- The administrator predicate is a fixed-search-path security-definer membership check on `auth.uid()`. Snapshot trigger is security-definer with a fixed search path; timestamp trigger preserves author/creation values on UPDATE. Constraints and the three trigger events were inspected. Locally, PGlite tests exercise anonymous, non-admin and admin roles, drafts, published rows, version access and archive behavior. These tests are not hosted JWT/API tests.
- Server-side actions call `requireAdministrator`, which verifies the Supabase user and administrator membership; the database checks administrator status independently. Form inputs are validated with Zod, the public library has bounded title search/page sizes, and publication requires a UI confirmation. Direct API clients with administrator credentials do not go through that confirmation. There is no application-level rate limiter for shared-query reads or admin actions; upstream platform quotas should not be assumed sufficient for abuse control. PostgreSQL CHECKs bound trimmed title/SQL lengths, not raw whitespace-padded direct-API inputs; authenticated administrators can bypass application validation. Consider a reviewed, owner-approved hardening migration for raw length, least-privilege column writes and limits if direct admin API access is in scope.
- Source and built browser chunk scans found no `DATABASE_URL`, `SUPABASE_SERVICE_ROLE`, or `SUPABASE_SECRET_KEY` references in searched client assets. Public Supabase keys are intentionally public, not secrets. This limited pattern scan is not a complete credential or Git history audit.

## Accessibility and regression cleanup

- Added a real space between the visible brand words so the accessible link name contains the visible label. Made the search button's accessible name include its visible `Search ⌘ K` text and an explanatory shortcut. Corrected optional shelf fallback/loading labels to match visible text; removed an unnecessary editor wrapper aria-label while retaining the CodeMirror content's label. Improved the disabled rollback control's text contrast.
- A non-interactive empty featured placeholder could intercept pointer events after its 3D transform. Its pointer hit-testing is disabled without disabling its rendering or the actual-component 3D effects; shelf controls remain interactive.
- Reproduced the seven previously reported frontend failures on both baseline `021eab6` and current `8a6f455`; a concurrent run exposed an eighth timing failure on both. Root causes: two tests assumed an obsolete one-resource production fixture; two tests identified the shared Three.js chunk rather than the optional shelf-specific module and the prior shelf label; other tests assumed old theme colors, old 3D renderer power preference, and short startup timeouts, while shelf auto-activation could race a manual click. Some earlier runs failed before reaching later stale assertions. Real 3D effects were preserved.
- Tests were corrected to cover the current empty/live catalog separately and retain the one-to-zero accessible search announcement check with the explicit development-only fixture; the optional shelf download checks target its own module rather than the shared library, preserving the no-optional-shelf-download assertion. The shelf auto-load test scrolls into view and exercises a real subject button; the software WebGL timeout reflects startup in this environment. The renderer still must request its configured high-performance context with major-caveat protection. Tests were not deleted.
- A development fixture run emitted React hydration mismatch warnings involving DOM attributes written by the existing 3D scroll rig on client navigation. The fixture test passed; the warning merits separate investigation without removing the 3D choreography.
